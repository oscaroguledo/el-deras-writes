# Deployment

Backend on **Render**, frontend on **Cloudflare Pages**, database on Neon (PostgreSQL).

## Backend (Render)

1. Render dashboard → New → Blueprint → pick this repo. `render.yaml` defines the service
   (build `pip install -r requirements.txt`, pre-deploy `alembic upgrade head`, health check `/health/`).
2. Set the variables marked `sync: false` in the dashboard:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | your Neon connection string |
   | `ADMIN_EMAIL`, `ADMIN_PASSWORD` | owner account (12+ chars), created at startup |
   | `FRONTEND_URL` | your Pages URL, e.g. `https://el-deras-writes.pages.dev` (or custom domain) |
   | `CORS_ALLOWED_ORIGINS` | same origin(s), comma-separated |
   | `CORS_ALLOWED_ORIGIN_REGEX` | optional, for preview URLs: `^https://([a-z0-9-]+\.)?el-deras-writes\.pages\.dev$` |
   | `BREVO_API_KEY`, `BREVO_FROM_EMAIL`, `SUPPORT_EMAIL` | optional, enables emails |

   `SECRET_KEY` is generated by Render. Never put real values in files in this repo.
3. Check `https://<service>.onrender.com/health/` returns `healthy`.

## Frontend (Cloudflare Pages)

**Option A: GitHub Action (included).** Create a Pages project (Workers & Pages → Create → Pages → Direct Upload)
named `el-deras-writes`, then in the GitHub repo add:

- Secrets: `CLOUDFLARE_API_TOKEN` (permission *Cloudflare Pages: Edit*) and `CLOUDFLARE_ACCOUNT_ID`
- Variables: `VITE_API_URL` (the Render URL, no trailing slash) and optionally `CLOUDFLARE_PAGES_PROJECT`

`.github/workflows/frontend-deploy.yml` then type-checks, builds and deploys on every push to `main`
that touches `frontend/`. Without the secrets it skips itself.

**Option B: Cloudflare's Git integration.** Connect the repo; root directory `frontend`,
build command `npm run build`, output `dist`, env var `VITE_API_URL`.

`public/_redirects` makes client-side routes work and `public/_headers` sets security and cache headers.

## Order of operations

1. Deploy the backend, note its URL.
2. Set `VITE_API_URL` and deploy the frontend, note its URL.
3. Put the frontend URL into the backend's `FRONTEND_URL` / `CORS_ALLOWED_ORIGINS`.
